# TextViewer v0.0.4

## 新增

- 增加字体选择按钮，支持搜索系统字体和预览；应用后记住选择，打开、新建、另存为及重启后继续使用。选择“自动”恢复文本和代码各自的默认字体。
- 增加保存编码切换：UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM、GB18030，可从状态栏或设置菜单选择。以目标编码保存当前正文，不重新解释已打开文件。
- 增加换行格式切换：Windows 使用 CRLF，Unix 和 Linux 使用 LF；支持从状态栏或设置菜单修改。
- 增加 JSON 格式化，可从代码格式菜单、编辑区右键或 Ctrl+Shift+J 使用。采用两空格缩进，保留字段顺序、重复键、数字原文和转义，支持一次撤销。

## 修复与性能

- 仅修改编码或换行格式也会提示未保存；后台保存固定使用开始保存时的文本、编码和换行格式，避免把后续修改误标为已保存。
- 移除普通 UTF-8 打开路径中重复的全文校验，保留解码验证和 GB18030 回退；缓冲区创建完成后再次检查取消状态。
- 系统字体只在首次打开字体选择器时枚举并缓存，不增加文件打开或每帧重绘的枚举成本。
- 本机约 100 MiB 多行 TXT 的载入从约 595 ms 降至 558 ms，JSON 载入约 478 ms。自动换行仍需渐进构建显示索引；这组样本的 TXT 索引另用约 1.39 s，不能代表所有文件和硬件的耗时。
- JSON 格式化在后台执行，可在应用结果前取消；无效、取消或已过期的结果保留原文，成功后保留编码、换行格式和此前撤销记录。

## 使用与兼容

- JSON 格式化只接受严格 JSON，不支持 JSONC 注释或 JSON5。输入上限 128 MiB，预估缩进输出上限 256 MiB，超过限制时保留原文。
- 本机约 100 MiB JSON 的格式化计算约 1.06 s、累计分配约 235 MiB，不含原文和应用结果的编辑缓冲区；格式化不会在打开文件时自动执行。
- 提供自动选择 x64 / ARM64 的合并安装包及两个架构的完整便携包。旧版本可通过“设置 → 检查更新”获取此版本。
- 本地安装验收使用隔离目录和独立应用身份；真实已安装应用的升级、重启及 ARM64 真机安装未包含在此验收中。

新版右键身份包仍使用自签名，更新后启用右键可能需要用户再次确认信任并处理 Windows 管理员确认。安装程序不会自动导入证书。
